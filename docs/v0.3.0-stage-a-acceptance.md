## 开测准备

- 两台 Windows（控制端、被控端），被控端接两台物理显示器并设为「扩展」；另备一部 Android 手机。被控端旁要有人，以便恢复显示器、解锁或重新启用服务。
- 只安装候选包成品。Android 同时安装同一构建、签名一致的启动器与配对伴侣；Moonlight 仍是独立应用。先记录 Android 之前是否在 Moonlight 配对过。Windows 记录使用的是通用安装器还是主机安装器。
- 两台 Windows 和手机先加入同一组网。F03 用独立的验收服务、数据目录和一次性验收密钥。正式服务已选当前这台常开的 Windows；本机已有预览服务在 Tailscale 地址的 8765 端口响应，正式配置与其他设备能否访问仍待验证，部署见 [激活服务说明](../server/README.md)。不要用正式密钥做吊销测试。测试时只使用空白桌面或记事本，不记录任何密钥、令牌、管理密码、协作码或完整机器指纹。

## A1 · F01 隐私屏

先关闭自动锁屏，避免 Windows 锁屏掩盖隐私屏消失的时机。测试 Ctrl+Alt+P 时，用**被控端物理键盘**。

| 项目 | 怎么验 | 本轮结果 |
| --- | --- | --- |
| 黑屏与本地输入 | 设为「黑屏」，控制端连接。两块物理屏均为黑色；控制端仍看到真实桌面，能用键鼠操作记事本；在被控端用物理键鼠，不能操作该桌面。 | 待验 |
| 图片及坏图回退 | 连接前选一张不含个人信息的 JPG/PNG。连接后检查两块屏被铺满，控制端仍看桌面；断开后把所选测试文件替换为损坏文件，重连应回退纯黑，设置页有失败提示。 | 待验 |
| 本地退出与自动恢复 | 串流时按 `Ctrl+Alt+P`，被控屏恢复且本次连接不再遮挡；下一次连接应重新遮挡。另开一场串流，不按热键就断开，检查遮罩自动撤掉。 | 待验 |
| 串流中改设置 | 本次串流设为黑屏，控制端通过串流操作被控端设置，切换到测试图片。当前应仍为黑屏，断开并重连后才显示图片。切成「关闭」后，下一场应全程无遮罩。 | 待验 |
| 只留托盘 | 关闭主窗口但不退出托盘进程，复验黑屏、图片、物理热键和断开恢复；不要用「立即预览」代替实际串流。 | 待验 |

## A2 · F02 断开自动锁屏

先把隐私屏设为「关闭」。计划中的旧勾来自 `v0.3.0-beta.1`、CI #45 的双机记录；以下是当前候选包的复验。

| 项目 | 怎么验 | 本轮结果 |
| --- | --- | --- |
| 开关开／关 | 开：正常串流后退出，从控制端断开起计时，被控端 3 秒内进入 Windows 锁屏界面且没有强哥远程弹窗。关：重复操作，应停在桌面。只留托盘时复测。 | 待验 |
| 从未连接 | 新登录后仅启动托盘，不发起串流；等待几次轮询，应保持桌面，不弹提示。 | 待验 |
| 轮询失败 | 有条件时在可就地恢复的验收机制造一段**已确认是探针失败**、而非正常断开的窗口，检查未知状态期间不锁屏、不弹提示。恢复后若探针确认曾观察到的串流已经结束，则可按正常断开规则处理。只拔网线或结束 Moonlight 并不能保证是探针失败；无法确认则保留待验，不能记通过。 | 待验；已有模拟回归 |

## A3 · F03 在线激活

按下列顺序执行。先测离线和服务停机，**最后才吊销**。不要为了加快复核改系统时间或清理正式用户数据。

| 项目 | 怎么验 | 本轮结果 |
| --- | --- | --- |
| 全新安装 | 在无旧激活的 Windows 与 Android 环境启动应用；未填密钥不能进主页，Windows 不应启动主机托盘服务。 | 待验 |
| 错误密钥／地址 | 试一条输错的密钥，应显示「密钥不正确」。用未使用的有效验收密钥，填同组网内确认没有监听的地址/端口，应显示「连不上激活服务器」；恢复正确地址后该密钥仍可用。 | 待验 |
| 一码一次 | 第一台 Windows 正确激活，第二台用同一枚密钥应提示「该密钥已被使用」且仍停在激活页。第二台和 Android 用各自的新密钥继续测试。 | 待验 |
| 断网重启与服务器停机 | 先让已激活设备离线并重启，确认进入主界面。再让客户端联网、仅关闭验收激活服务，彻底退出并重开应用，仍可进入主界面。分开记录两种结果。 | 待验 |
| 吊销 | 吊销一台验收设备，先确认它未联网复核时仍可启动。恢复连接，等待该设备到了复核时间并成功复核，应回激活页显示「本设备已被作者停用」；随后重启也不能进主页。新激活后正常复核最多每周一次；提前安排日期，若时间尚未到就记待验。 | 待验 |

Windows 的两项匹配容差和「本机硬件有变化」提示有自动测试；不必拆换生产电脑硬件来模拟故障。

## A4 · 三项结论单独留档

| 项目 | 要记录的结论 | 本轮结果 |
| --- | --- | --- |
| Android 首次串流 | 在未被 Moonlight 配对过的主机上验证：能否只用强哥远程完成配对后进入可操作串流。若不能，在 Moonlight 内配对后分别验证从 Moonlight 主机列表、从强哥远程快捷入口发起串流，记录画面与触控/输入是否正常。候选包走 Moonlight 主界面及其公开快捷入口，不把源码检查当真机结果。 | 待验 |
| 无显示器／锁屏画面 | 被控端分别在没有活动显示器、连接显示器但锁定 Windows 的情况下尝试串流；分别记连接是否成功、看到黑屏／锁屏／桌面的哪一种、键鼠是否有效。 | 待验 |
| Sunshine 重启恢复 | 保存工作后，在有人可就地恢复的被控机正常重启 Windows。分别记录重启后 `SunshineService` 状态、登录后托盘是否恢复、重新串流是否成功与耗时。「当前正在运行且设为自动」不能替代重启测试。 | 待验 |

每行结果用「日期 / 构建号 / 两端系统和设备类型 / 通过、失败或待验 / 现象或耗时」回填；A4 允许记明确的「不支持」结论，不允许留空当完成。A1–A3 的问题修好并复验后才勾开发计划。发布动作另需当前提交的分析、测试与 CI 全绿，Windows 两款安装器、Android 独立双 APK、激活服务和 keygen 齐全。发给课题组前必须用同一发布签名的双 APK，不发调试签名包。
